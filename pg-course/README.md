# Установка учебного стенда

Программа практических занятий, назначение файлов и команды работы находятся в
[общем README](https://github.com/tsenturion/PostgreSQL_Architecture_for_Enterprise_Systems#readme).
Здесь собраны параметры первоначальной подготовки и обновления.

## Виртуальная машина

Используем отдельную Ubuntu Server в VirtualBox. Установщик рассчитан на Ubuntu 22.04,
24.04, 26.04 и 26.10; практическая работа стенда проверена на 26.04.
Для занятий выделяем 2 vCPU, желательно 4 ГиБ RAM и динамический диск 25–30 ГиБ.
Минимальная память — 3 ГиБ. Мониторинг и отдельное восстановление включаем по необходимости.

Перед установкой нужны интернет, доступ root и настроенная сеть ВМ. Установщик не меняет
SSH, Netplan и параметры VirtualBox. Проверяемый адрес публикации должен уже принадлежать ВМ.
Нужно не менее 8 ГиБ свободного места в файловой системе стенда и 4 ГиБ — Docker;
если это одна файловая система, требования не суммируются.

## Первый запуск

Команды выполняем в ВМ от root. Если Git ещё не установлен:

```bash
apt-get update
apt-get install -y --no-install-recommends git
git clone https://github.com/tsenturion/PostgreSQL_Architecture_for_Enterprise_Systems.git
cd PostgreSQL_Architecture_for_Enterprise_Systems
bash pg-course/install.sh --check
```

После проверки выбираем один вариант установки. Для доступа только на `127.0.0.1` внутри ВМ:

```bash
bash pg-course/install.sh
```

Либо для подключения к стенду с других компьютеров сразу указываем IP своей ВМ, например:

```bash
bash pg-course/install.sh --bind-address 192.168.0.35
```

Для доступа к loopback-публикации с компьютера преподавателя или студента используем SSH-туннель.
В следующем примере `ubuntu@192.168.0.35` заменяем адресом своей ВМ:

```bash
ssh -4 -N -L 5432:127.0.0.1:5432 -L 6432:127.0.0.1:6432 -L 3000:127.0.0.1:3000 ubuntu@192.168.0.35
```

Первая установка загружает пакеты, образы и зависимости. При работе с архивом вместо Git
распаковываем каталог `pg-course` и запускаем `bash install.sh` из него.

## Параметры

| Параметр | Значение |
|---|---|
| `--check` | Предварительная проверка ОС, памяти и места без установки. Проверка всех портов выполняется позже, при подготовке конфигурации |
| `--bind-address IP` | Адрес публикации; по умолчанию `127.0.0.1` |
| `--orders ЧИСЛО` | 1 000–100 000 заказов; по умолчанию 50 000 |
| `LAB_HOME` | Отдельный каталог установки; по умолчанию `/opt/pg-course` |

Пример меньшего набора данных в другом каталоге:

```bash
LAB_HOME=/srv/pg-course bash pg-course/install.sh --orders 10000
```

Адрес, размер начального набора данных и пароли сохраняются. При повторном запуске
параметры повторять не нужно; существующая база заново не наполняется.
Смена `--orders` не меняет уже созданные данные. Если используется другой `LAB_HOME`,
его нужно указывать и при последующих запусках.

## Повторный запуск и обновление

Для обновления из исходного репозитория:

```bash
cd /root/PostgreSQL_Architecture_for_Enterprise_Systems
git pull --ff-only
bash pg-course/install.sh
labctl check
```

Путь к исходному репозиторию заменяем своим. Повторный запуск установленной копии без
получения новых исходников: `bash /opt/pg-course/install.sh`.

Установщик сохраняет `.env`, сертификаты, данные, резервные копии и динамическую конфигурацию
Patroni в DCS. Генерируемые `compose.json` и `config/` обновляются из шаблонов. Изменения,
которые должны пережить повторную установку, вносим в `scripts/configure.py`.
Поля `bootstrap.dcs` применяются только при первой инициализации кластера.

Повторный запуск поднимает основные компоненты, в том числе остановленные во время опыта.
При изменении конфигурации HAProxy проверяет её и перезапускает балансировщик. На время
обновления завершаем учебную нагрузку. Если `.env` утрачен при существующих данных PostgreSQL,
сначала восстанавливаем исходный файл: новый набор паролей автоматически не создаётся.

## Если установка прервалась

Журнал указан в сообщении об ошибке и сохраняется в `/opt/pg-course/logs/install/`.
После устранения причины повторяем запуск из актуальных исходников. Уже созданная база
не пересоздаётся; незавершённое первоначальное наполнение выполняется транзакционно.

Если команды управления уже установлены:

```bash
labctl status
labctl diagnose
systemctl status docker --no-pager
```

Общее обновление ОС, удаление сторонних контейнеров и очистка кешей в установку не входят.
