## Блокировки и наблюдение за ожиданиями

```sql
SET application_name = 'lecture04-A';
SET idle_in_transaction_session_timeout = '30min';
SET lock_timeout = '8min';
SET statement_timeout = '9min';
CREATE TABLE IF NOT EXISTS lab.lock_resources (
    resource_id integer PRIMARY KEY,
    remaining integer NOT NULL CHECK (remaining >= 0),
    revision integer NOT NULL DEFAULT 0
);
INSERT INTO lab.lock_resources(resource_id, remaining, revision)
VALUES (1, 10, 0), (2, 10, 0)
ON CONFLICT (resource_id) DO UPDATE
SET remaining = EXCLUDED.remaining, revision = EXCLUDED.revision;
SELECT resource_id, remaining, revision
FROM lab.lock_resources ORDER BY resource_id;
```

[русской документации `pg_blocking_pids()`](https://postgrespro.ru/docs/postgresql/18/functions-info#FUNCTIONS-INFO-SESSION-TABLE)

```sql
SET application_name = 'lecture04-N';
SET idle_in_transaction_session_timeout = '30min';
SET lock_timeout = '8min';
SET statement_timeout = '9min';
SELECT w.application_name AS waiting_session,
       w.pid AS waiting_pid,
       w.wait_event_type,
       w.wait_event,
       clock_timestamp() - w.query_start AS query_age,
       b.application_name AS blocking_session,
       b.pid AS blocking_pid,
       b.state AS blocking_state,
       clock_timestamp() - b.xact_start AS blocking_transaction_age
FROM pg_stat_activity AS w
CROSS JOIN LATERAL unnest(pg_blocking_pids(w.pid)) AS p(pid)
JOIN pg_stat_activity AS b ON b.pid = p.pid
WHERE w.application_name LIKE 'lecture04-%'
ORDER BY w.pid, b.pid;
```

[русской документации `pg_locks`](https://postgrespro.ru/docs/postgresql/18/view-pg-locks)

```sql
SELECT a.application_name,
       l.pid, l.locktype, l.mode, l.granted,
       l.relation::regclass AS relation,
       l.transactionid,
       l.waitstart,
       clock_timestamp() - l.waitstart AS lock_wait_age
FROM pg_locks AS l
JOIN pg_stat_activity AS a ON a.pid = l.pid
WHERE a.application_name IN ('lecture04-A', 'lecture04-B')
  AND (l.relation = 'lab.lock_resources'::regclass
       OR l.locktype = 'transactionid')
ORDER BY a.application_name, l.locktype, l.granted;
```

## Производительность и архитектурные приёмы

```sql
BEGIN;
SELECT resource_id, remaining
FROM lab.lock_resources
WHERE resource_id IN (1, 2)
ORDER BY resource_id
FOR UPDATE;
UPDATE lab.lock_resources
SET remaining = remaining - 1, revision = revision + 1
WHERE resource_id IN (1, 2);

```

```sql
UPDATE lab.lock_resources
SET remaining = remaining - 2, revision = revision + 1
WHERE resource_id = 1 AND remaining >= 2
RETURNING resource_id, remaining, revision;

SET remaining = remaining - 100, revision = revision + 1
WHERE resource_id = 1 AND remaining >= 100
RETURNING resource_id, remaining, revision;
```

[русской документации SELECT](https://postgrespro.ru/docs/postgresql/18/sql-select#SQL-FOR-UPDATE-SHARE)

```sql
CREATE TABLE IF NOT EXISTS lab.lock_tasks (
    task_id integer PRIMARY KEY,
    state text NOT NULL CHECK (state IN ('ready', 'processing', 'done'))
);
INSERT INTO lab.lock_tasks(task_id, state)
VALUES (1, 'ready'), (2, 'ready'), (3, 'ready')
ON CONFLICT (task_id) DO UPDATE SET state = EXCLUDED.state;
BEGIN;
WITH candidate AS (
    SELECT task_id FROM lab.lock_tasks
    WHERE state = 'ready'
    ORDER BY task_id LIMIT 1
    FOR UPDATE SKIP LOCKED
)
UPDATE lab.lock_tasks AS t SET state = 'processing'
FROM candidate AS c
WHERE t.task_id = c.task_id
RETURNING t.task_id, t.state;
```

```sql
BEGIN;
WITH candidate AS (
    SELECT task_id FROM lab.lock_tasks
    WHERE state = 'ready'
    ORDER BY task_id LIMIT 1
    FOR UPDATE SKIP LOCKED
)
UPDATE lab.lock_tasks AS t SET state = 'processing'
FROM candidate AS c
WHERE t.task_id = c.task_id
RETURNING t.task_id, t.state;
COMMIT;
```
